# Thinkback 记忆系统巡检报告——生产级与主流对齐(2026-09)

> 巡检日期:2026-09-10。基线:工作树(含 staged 的 `src/innies_memory/ → src/` 平移重命名,未提交)。
> 本报告基于两轮共识评审(14 项决策)产出,决策记录见 §6。

## 0. 结论摘要

**架构不落后,工程化在倒退,评测是隐藏资产。**

- **三层架构(PG 短期/会话摘要/mem0 长期抽取 + Milvus)与主流设计同源**,底层直接内嵌 mem0 库,天然对齐;时态有效性(`valid_at/invalid_at`)、衰减(`MemoryDecaySweeper`)、三重隔离等能力**超出** mem0 开源版。
- **工程化是最大短板**:发布链路(build→push→三环境 gitops)**零质量门槛**——含 lint/test 的 `ci.yml` 在 `f2ba665` 中被删除;无 metrics;LLM/embedding/mem0 调用无统一超时与熔断。
- **当前工作树是红的**:重命名只搬了文件,**205 处 import 未改**,服务无法启动、测试无法运行。
- **评测能力被低估**:codebase 内已有带硬门禁的真实依赖质量回归(recall@10≥0.95、污染率≤0.02、跨用户泄漏=0)与中文回放评测,但**未接入任何 CI**,纯手工。

**与主流的对齐动作不是换架构,而是:把评测资产接入 CI、补答案质量与时间推理类评测口径、补齐工程化 P0。**

## 4. 主流差距矩阵

对照口径:Mem0 论文(LOCOMO:四类问题 single-hop/temporal/multi-hop/open-domain;指标 LLM-as-Judge + F1;效率口径 p95 延迟 + token 成本)与 LongMemEval(五能力:信息抽取、多会话推理、时间推理、知识更新、拒答;商业助手在持续交互中准确率掉 30%)。

| 维度 | Thinkback 现状 | 主流参照 | 判定 |
|---|---|---|---|
| 记忆引擎 | 直接内嵌 `mem0ai ^2.0.20` | mem0 本尊 | ✅ 天然对齐 |
| 架构范式 | 三层:PG 短期 + 会话摘要 + LLM 抽取长期 | mem0 extract→consolidate→retrieve;LongMemEval 的 session decomposition | ✅ 设计同源 |
| 冲突消解 | mem0 内置 ADD/UPDATE/DELETE/NOOP + 自建 slots/canonical 归一 + `conflict_pollution≤0.02` 门禁 | mem0 内置 | ✅ 超出(槽位归一) |
| 时间感知 | `valid_at/invalid_at` 迁移 + 时态测试;`last_recalled_at/recall_count` | Zep bitemporal;LongMemEval temporal reasoning | 🟡 存储对齐,**评测缺 temporal 任务类**(P1-4) |
| 遗忘/衰减 | `MemoryDecaySweeper` + decay 测试 | mem0 开源版无;Zep 有 | ✅ 超出 |
| 隔离 | user/character/现实-剧情三隔离 + `cross_user_leak=0` 门禁 | 多数开源只做 user 级 | ✅ 超出 |
| 拒答/抽象 | 未见评测覆盖 | LongMemEval abstention | 🔴 缺口(P1-4) |
| 评测:存储质量 | recall@10/precision@10/污染/泄漏等 9 项硬门禁,已代码化 | mem0 论文之外的自加项 | ✅ 资产,待接 CI(P0-2/5) |
| 评测:答案质量 | 无 JGA/F1、无 LLM-as-judge | LOCOMO 主口径 | 🔴 缺口(P1-4,含一次性公开基准校准) |
| 评测:效率口径 | zh_replay 已报召回 p50/p95 + token 注入量,"分数与成本成对报告" | mem0:91% p95 降低、>90% token 节省 | ✅ 口径一致 |
| 检索 | Milvus 向量 + query_slots 约束 | mem0 默认向量;主流趋势含混合检索 | 🟡 对齐,P2 观察 |
| API 形状 | 自有 HTTP + gRPC 双协议 | mem0 REST | 🟡 共识:只审查语义,不重写 |
| 图记忆 | 无 | mem0-graph(+2%)、Zep | ⛔ 显式决策不跟,见 §6-D1 |
| 生产工程 | CI 零门槛、无 metrics、无熔断 | 主流开源产品化基线 | 🔴 **最大差距块**(P0-2~5) |

**结论:功能面与主流互有胜负且总体不落后;差距集中在(i)答案质量/时间推理评测口径、(ii)生产工程化。**

## 6. 显式决策记录(ADR)

- **D1 不跟 Zep 式时序知识图谱**:当前向量 + 关系型 + 时态字段满足场景;图谱的运维与复杂度成本不值。演进路径保留:`valid_at/invalid_at` 已具备时态基础,未来可平滑升级。参照:mem0-graph 仅 +2%(arXiv 2504.19413)。
- **D2 mem0 底层保留,API 只审查不重写**:已是主流本尊;自有 HTTP+gRPC 契约的语义向 mem0 REST 惯例对表,作为文档化审查项。
- **D3 gRPC 保留**:真实现且有测试;无论有无消费方都补标准 health 协议;后续投入档位待消费方确认(F2)。
- **D4 工具链 uv + Python 3.12**:部署物(3.12-slim)为准。
- **D5 破坏性变更放行**:无存量生产数据(部署链无生产环境),collection/镜像/包名一次改到位。
- **D6 评测分层**:日常门禁 = 中文场景回放 + 存储质量硬门禁(进 CI nightly);公开基准只做一次性校准,不进 CI。
- **D7 f2ba665 删除物按"重写"处理**:CI 重写更简版本;k8s 清单按需新写;评测文档以代码 + 本报告 §4 口径为准,不 git 恢复。
