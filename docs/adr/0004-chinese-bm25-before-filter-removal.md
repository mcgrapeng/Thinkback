# 中文词命中先于硬过滤下线

固定槽位引擎与词典交集硬过滤暂不删除。先重建 Milvus collection 使用中文分词器，让中文 BM25 真正生效；之后按记忆类型逐个下线硬过滤，每类下线都要有评测支撑。

理由：实测 mem0 2.2.1 的 BM25 只对英文与型号词命中，中文查询的关键词分为零；entity matching 依赖英文模型，对中文垂类没有收益。照原计划删掉硬过滤，中文领域词召回会退化成纯语义。实体匹配不能作为中文方案的依据。

垂类词表随之降级：先做抽取 prompt 的提示与类型 metadata 标签，不承担检索期过滤；是否需要检索期过滤交给评测决定，不另起一套硬过滤绕开这个决定。

落地后的实测（2026-10-28，40 条垂类语料、真实栈）：

- 中文 BM25 生效后，下线硬过滤的前提满足了。真正卡住召回的不是本地词典
  交集，而是 mem0 的 **threshold 只卡语义分**：源码注释写明「Threshold gates
  the semantic score BEFORE combining -- candidates below the threshold are
  excluded even if BM25/entity would boost them」。中文场景里语义分不高但词
  命中的事实很常见（问「RCA 槽排在第几步」，记忆写的是「RCA 槽排在第 3 道」：
  语义分 0.39、BM25 0.69），语义门直接把它挡掉。
- 放行条件因此改成「语义分达标 **或** 综合分达标」：引擎的语义门关掉
  （threshold=0），服务侧拿分数分解自己判。候选放宽到两倍，最终仍按
  l3_limit 与 token 预算裁剪。
- 效果：真实栈评测从 38/40 到 40/40。硬过滤本身已经不在 L3 路径上（只有
  单槽位精确提问还按槽位收窄），词典交集过滤降级为 L1/L2 侧的口径。
- 垂类词表仍然不承担检索期过滤：词命中由引擎的 BM25 负责，我们不再另起一套。
