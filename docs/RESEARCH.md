## 0. 结论先行（三句话）

1. **三层架构不落后**：学界 2026 收敛的记忆分类（episodic/semantic + 显式/隐式表征、形成/演化/检索算子）与我们的 L1/L2/L3 同构；产品端"显式记忆 + 隐式历史"双轨（ChatGPT/Claude/豆包）我们也有对应物（L3 离散原子记忆 + L2 摘要 + journal 回放）。
2. **实现载体有两处硬代差**：①mem0 锁定 `0.1.118` 落后**两个大版本线**（v2.0 的三信号混合检索与单遍 ADD-only 抽取是纯向量检索时代的差距）②L2 是 10 轮拼接占位，落后于自家 V2 路线图与 ChatGPT"持续综合摘要"范式各一代。
3. **治理面反而超前**：自建删除墓碑、幂等锚点、槽位 supersede（写入端知识更新）恰是业界 2026 才普遍强调的能力（MemoryAgentBench 把"选择性遗忘/知识更新"列为核心能力）；全链路真实测试（HTTP 26/26、gRPC 17/17、压测 EXIT=0）是多数开源项目不具备的工程资产。

## 1. 判定框架（本次调研的定调）

- **参照系**：生产实践主流为主（大多数线上记忆系统在用什么），开源框架代际为辅；学术前沿只做雷达，不作为"落后"依据。
- **阈值**：影响正确性/数据安全、或造成明显体验差距（召回质量、跨会话一致性）→ 算落后；功能新颖、叙事更新（"context engine"）→ 记雷达不触发动作。
- **约束**（软约束，框内为主 + 标注放开收益）：内网部署、PG + Milvus、1-2 人维护力、进程内嵌入形态。

## 2. 现状锚点（我们的栈，2026-09）

`Mem0 0.1.118 embedded library（2025-09 版）+ Milvus（向量）+ PG（业务索引/任务/journal）+ 自建正则槽位引擎 + 自建删除墓碑/幂等/背压管线`；L2 为拼接式摘要（V1 占位）；全链路真实测试资产齐备。

## 3. 业界全景摘要

### 3.1 产品范式（已验证：OpenAI/Anthropic 官方文档）

- **ChatGPT**：已从离散 saved memories 转向「持续更新的记忆摘要（Memory Synthesis）」+ 来源角标（用了哪条记忆、为什么）+ 就地纠错 + 作用域分级（临时会话不读不写 / 项目级 / 用户级）。官方承认旧离散条目"易过期、互相矛盾、要人管"。
- **Claude**：客户端文件式记忆（memory tool = `/memories` 目录文件操作，存储在应用侧）+ just-in-time 检索 + 服务端 compaction 配合；2026-08 起 Cowork 与 chat 共享统一记忆。
- **国内**：豆包/千问/Kimi/腾讯 Hy-Memory 普遍走"显式记忆 + 隐式历史引用"双轨。

### 3.2 开源格局（star 为 2026-09-07 实测）

| 梯队 | 项目 | 与我们的关系 |
| --- | --- | --- |
| 头部 | mem0 64.8k、**OpenViking（字节）35.9k**（8 个月，最猛，AGPL）、Graphiti 30.7k、Cognee 30.5k、Supermemory 29.2k、Letta 24.6k | mem0=本体；Graphiti=时序互补；OpenViking=范式替换候选（license 红线） |
| 新星 | Memori 16.5k（行为记忆）、memU 14.4k（文件式 Wiki）、EverOS 12.7k（本地优先）、MemOS（国产）11.2k | 均为互补路线 |
| 弃坑/停滞 | Letta V1 封存、LangMem 停更 11 月、memobase 停 8 月、A-Mem 论文摆件 | 避坑 |

**热度报告核心判定**：2026 年没有任何项目能在"Mem0 embedded + Milvus + PG 业务索引"这个具体形态上整体替代 Mem0；增量在「时序/图补强」（Graphiti）与「文件式记忆」（memU/EverOS）两个方向。

### 3.3 2026 生态共识（table stakes）

记忆类型分层叙事、三信号混合检索（语义+BM25+实体，**纯向量出局**）、遗忘/矛盾处理（"只增不删"视为缺陷）、热路径/后台萃取分离、多租户 scope 隔离、评测军备（LoCoMo 已通胀：各家自报 88~96 分因 judge/rerank 协议不同而不可比）、可观测/溯源、部署三件套（library/server/cloud）、Markdown 文件原生运动、"context engine"叙事取代"memory layer"。

### 3.4 学术雷达（2025-2026，仅记录不触发动作）

- 分类学收敛：CoALA 式 episodic/semantic/procedural + 表征三态（token/parametric/latent，arXiv 2512.13564）+ 生命周期算子（formation/evolution/retrieval，含遗忘）。
- 前沿方向：睡眠期巩固（Letta sleep-time、SCM 2604.20943）、记忆即推理（ReasoningBank、MemCoT）、测试时记忆（AgeMem）、受控遗忘（Oblivion 2604.00131）、RL 管理记忆（Memory-R1 2508.19828）、双时态知识图（Graphiti 2501.13956）。
- 基准现状：LoCoMo/LongMemEval 分数不可比；BEAM（ICLR 2026，1M/10M token）是当前最难且证明"长上下文不能替代记忆"；**无权威中文长期记忆基准**（明显空档）。
- 中文特有难题：token 计量跨模型倍数级差异（记忆预算需按目标模型重标定）；实体别名/简称频繁（实体链接错误率高于英文）。

## 4. 差距决策矩阵（核心交付）

判定：🔴 必须跟 / 🟡 值得跟 / ⚪ 可不跟（雷达）。优先级 P0 > P1 > P2。

| # | 差距项 | 判定 | 优先级 | 动作与成本 | 依据 |
| --- | --- | --- | --- | --- | --- |
| 1 | **L2 摘要 LLM 化**（拼接 → 结构化综合摘要） | 🔴 | **P0** | 复用 L3 异步管线模式后台生成；拼接版保留为降级路径；需摘要质量评测。约 1-2 周 | 自家 V2 路线图 + ChatGPT 范式双重确认的最大体验差距；三层架构中唯一"实现深度落后于设计"的层 |
| 2 | **mem0 0.1.118 → v2.0.20 升级** ✅ 已落地（2026-09-08） | 🟡 | **P1** | 破坏性迁移（prompt 改名 `custom_instructions`、SDK 面变化）；收益 = 三信号混合检索 + 单遍抽取延迟减半；须重跑全链路回归。约 1-2 周 | 两代大版本代差；正确性无差距（全链路已验证），属体验/性能级；不为厂商"library=原型"的话术买单，embedded 形态保持 |
| 3 | **混合检索**（语义+BM25+实体） ✅ 随 #2 获得 | 🟡 | P1·随 #2 获得 | 升级 mem0 v2 自动获得，不自建 PG FTS | 纯向量检索在多跳/时序/开放域已是短板（各系统 LoCoMo 分项规律一致）；中文 BM25 + 实体别名表是低成本召回补强 |
| 4 | **多副本任务表乐观锁**（自家 B-3 遗留） | 🔴 | P1·扩容前置 | `ins_memory_task` 加版本列；claim/save 改 CAS | 非业界差距但 ARCHITECTURE §6.2 硬前置；2 副本部署已存在丢失更新窗口 |
| 5 | **槽位引擎去留** | 🟡 | P1·保留为补偿索引 | 保留；随 #2 评估实体链接质量后用真实流量 A/B 决定删留；不扩大词表投入 | 全链路测试证明其是召回承重墙；与 v2 实体链接部分同构；往硬编码加码与生态方向相反 |
| 6 | **时序：新事实优先** ✅ 已落地（2026-09-08） | 🟡 | P2 | 检索端按记忆时间戳新优先排序（写入端 supersede 已有） | 学界硬建议（"为事实会变建模时间"）；staleness 是公认开放难题 |
| 7 | **遗忘/衰减治理** ✅ decay 已落地（2026-09-09，默认关闭按需启用） | 🟡 | P2 | importance/merge/decay/eviction 四杠杆中最轻的 decay 起步；sleep-time 式异步 | 学术共识 + 生态共识；但产品无显式需求且显式删除已有；ADD-only+检索端裁决路线也成立 |
| 8 | **质量评测基准（中文）** ✅ harness 已落地（2026-09-08 基线 7/7，p50=15ms） | 🟡 | P2 | 从真实流量抽对话回放建小型中文评测集；分数配 token 成本与延迟成对报告 | 无权威中文基准（空档=机会）；榜单数字不可比，"用自己的回放做应用级评测"是学界/业界共同结论 |
| 9 | **可解释性**（recall 返回记忆来源+理由） | ⚪ | P2·雷达 | API 已有 source/metadata 雏形，按上游 UX 需要再开 | ChatGPT 范式，但 UX 在上游；API 服务先备数据不先做交互 |
| 10 | **embedded → 自托管 server** | ⚪ | 雷达 | 保持 embedded（1-2 人维护下运维最简，PG/Milvus 资产不动） | 厂商生产推荐路径是 server/cloud，但其收益（审计/多租户 API key）我们由 PG 业务索引自建覆盖；若未来多业务方共用记忆服务再评估 |
| 11 | **文件式记忆 / 行为记忆**（memU/EverOS/Memori） | ⚪ | 雷达·可选试点 | 与 PG 业务索引天然分层；编码 agent 场景试点价值最高 | 互补非替换；2026 新战线观察 |
| 12 | **图数据库 / OpenViking / MemOS 替换** | ⚪ | 不动 | — | Mem0 v2 自己砍掉外置图（趋势：图数据库让位于实体感知混合检索）；OpenViking AGPL 传染性 + 范式重建；MemOS 自报数据待独立复现 |

## 7. 开源项目 → 本项目的优化与集成空间分析（补充任务核心）

对每个热门项目回答两个问题：**A. 能优化我们什么**（借思想/借组件/借配置）**B. 能否与我们集成**（我们引入它作组件，或它把我们当服务用）。

### 7.1 高价值发现（按投入产出排序）

| # | 来源项目 | A. 优化本项目的空间 | B. 集成空间 | 成本 |
| --- | --- | --- | --- | --- |
| O1 | **Graphiti（时序图）** | **双时态建模思想可以只借两列**：`ins_memory` 加 `valid_at/invalid_at`，检索端新事实优先——不必引入 Neo4j。边失效（矛盾自动 invalidation）与我们已有的槽位 supersede 互补 | 可作 L3 之上的时序关系层并存（Apache-2.0），但引入图库运维；**先借思想不引组件** | 低（两列+排序） |
| O2 | **Letta sleep-time/dreaming** | **L2 LLM 化与遗忘治理的实现蓝本**（源码级验证过）：伴生后台 agent 每 N 轮触发整理、memory_replace/insert/rethink 工具集、共享 memory blocks——正好是矩阵 #1（P0）和 #7（P2）的参考实现 | 不集成（其平台绑定），纯借模式 | 零（模式参考） |

| O4 | **mem0ai/memory-benchmarks** | 矩阵 #8（中文回放评测集）的现成实现载体：其开源评测框架支持自定义对话回放与 judge 配置 | 直接复用框架跑我们的真实流量回放 | 低-中 |

| O7 | **memU/EverOS（文件式）** | 导出层思路：把用户记忆以 Markdown 导出供 coding agent 复用 | 与 PG 索引天然分层，试点价值在编码场景 | 低 |
| O8 | **Supermemory** | 自动遗忘/矛盾处理思路（四杠杆的工程化） | 检索引擎替换候选（MIT 可本地）；非当前需要 | 中 |

| O10 | **MemOS MemCube** | 三态调度（plaintext/activation/parametric）是远期思想；latent/parametric 记忆超出当前产品形态 | 观察；TS 主栈迁移成本高 | — |

### 7.2 反向输出：本项目可作为集成方输出的资产

- **槽位引擎**（`domain/slots` 纯函数、中文实体抽取已实战）与**安全门禁词表**是热门项目普遍缺失的组件——若未来对外开源/共享，这是差异化贡献点。
- **全链路真实测试资产**（HTTP/gRPC/压测三套脚本）与治理面（墓碑/幂等/背压）是可复制的工程模式。

### 7.3 集成决策（已定案）

- **O1 时序两列 → P2**：`ins_memory` 加 `valid_at/invalid_at` + 检索端新事实优先。轻量双时态建模，在槽位 supersede 之外系统性解决 staleness 回潮；不引入图库。
- **O3 MCP server 入口 → 雷达**：零侵入适配层（FastMCP 包 `MemoryService` 五工具），等上游出现 coding agent 集成需求时一两天内可加。
- 其余 O2/O4 已分别并入矩阵 #1/#7 的实现参考与 #8 的实现载体；O6-O10 维持雷达/不做。
