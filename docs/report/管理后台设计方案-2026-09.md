# Thinkback 记忆管理后台设计方案（治理台 v1）

| 元信息 | 值 |
| --- | --- |
| 定位 | 内部运维/治理台（补齐三层架构 §0 登记的「人工治理台」缺口），非终端用户页面 |
| 架构 | 前后端分离：Monorepo `web/`（SPA）+ 现有 FastAPI 新增 `/admin/api` 路由；SPA 静态托管独立于服务镜像 |
| 无障碍 | WCAG 2.2 AA 硬验收（键盘全程可达 / 对比度 ≥4.5:1 / 焦点管理 / ARIA / 动态内容 announce） |

## 1. 架构与复用边界（不造轮子的执行面）

```text
web/                          # SPA（独立 npm 工程，uv 不管理）
  src/{app, pages, components, hooks, api, lib}
  TanStack Query 管服务端状态；Router 文件式路由；无全局状态库（不需要）
src/thinkback/api/admin/      # 新增管理路由（前缀 /admin/api）
  复用现有 service 公开方法 + 新增只读聚合端点
部署：web 构建产物 → nginx 静态托管（k8s configmap/deployment），
CORS 白名单 admin 域名；/admin/api 走内网 ingress + 共享 Bearer token（可关）
```

**后端新增端点清单**（现有 8 端点之外治理台必需；全部薄聚合，业务逻辑仍在 service）：

| 端点 | 用途 | 备注 |
|---|---|---|
| GET /admin/api/overview | 总览聚合（记忆/任务计数、L3 水位、readiness） | 复用 l3_background_status + 新计数查询 |
| GET /admin/api/memories | 多用户记忆检索（服务端分页/筛选/排序） | 现有 /memory/items 需 user_id 且无分页，不满足 |
| GET /admin/api/memories/{id}/source | source_refs 反链 journal 原文 | 治理台核心：核验抽取是否有源 |
| GET /admin/api/tasks | 任务列表（状态/年龄筛选） | 现有仅单任务查询 |
| POST /admin/api/rebuild | rebuild 受控触发 | service.rebuild 存在但**无 HTTP 路由**（事实） |
| GET /admin/api/audit | 审计查询 | 依赖新增 audit 表 + admin 中间件写入 |
| GET /admin/api/config | 只读配置视图 | 敏感值脱敏 |

**UI 轮子清单**（全部复用，禁自造）：shadcn/ui 全件、TanStack Table（headless 表格引擎）、TanStack Query（请求缓存/重试/失效）、Recharts（图表）、react-hook-form+zod（表单+校验，与后端 Pydantic schema 同构）、Sonner（toast）、vaul（mobile 抽屉）。唯一允许的自定义层：设计 token 与页面组装。

## 2. 设计系统基础

- **Token**：shadcn CSS 变量体系（HSL），语义色映射任务域 —— ACTIVE=emerald、SUPERSEDED=amber、DELETED=rose、SUPPRESSED=slate、RUNNING=blue、FAILED=red、DEAD_LETTER=violet；全部过对比度校验，**状态永不只靠颜色表达**（图标+文字 badge）
- **暗色**：`class` 策略双主题，图表随 token 切换；默认跟随系统
- **排版**：中文栈 `-apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`；数据密集基线 14px/1.5；ID 与时间戳 `tabular-nums` + 等宽字体；长 ID 提供 `font-mono` 截断+复制
- **密度**：表格 compact（行高 36px）、表单 comfortable；操作区最小触达 44×44px（移动端 WCAG 2.5.8）
- **中文文案**：全部 key 化（`t("task.status.dead_letter")`），单语 zh-CN，预留 i18n 逃生门

## 3. 逐页设计走查

### P1 总览 Dashboard

**目的**：10 秒回答「系统现在健康吗、有没有事要我处理」。

```text
┌ KPI 行（4 stat 卡，语义化 <dl>）────────────────────────┐
│ 活跃记忆总数 │ 进行中任务 │ 24h 失败任务 │ L3 队列水位   │
├───────────────────────────┬─────────────────────────────┤
│ 任务状态 24h 时序（面积图） │ L3 背景写状态卡（复用端点）  │
│                           │ worker/容量/水位进度条       │
├───────────────────────────┼─────────────────────────────┤
│ 依赖探针（PG/Milvus/mem0） │ Decay 概览（若启用）        │
└───────────────────────────┴─────────────────────────────┘
```

- **组件**：shadcn Card + Recharts AreaChart（提供「表格视图」切换与 sr-only 数据表）+ Badge
- **数据**：overview 端点，TanStack Query 30s 轮询；探针失败 → 顶栏全局 Alert（`role=alert`）
- **无障碍**：KPI 为 `<dl><dt><dd>`；图表有文字摘要 aria-label；轮询更新用 `aria-live=polite` 区域只播报状态**变化**
- **响应式**：≥1280 四卡一行；768–1279 两行两列；<768 单列 + 图表横向滚动；**移动端本页功能完整**（这是 on-call 首屏）

### P2 记忆浏览器（核心页）

**目的**：按用户/会话下钻记忆全量视图，核验每条记忆的来源与时间语义。

```text
┌ 筛选栏 ──────────────────┬ 数据表格（TanStack）────────────────┐
│ user_id（必填起步）        │ ID│摘要│槽位│状态│valid_at│invalid_at│
│ scope/session 下拉        │ 召回次数│更新时间 │ ⋯ 行操作         │
│ 状态多选 / 槽位 / 时间窗   │ 服务端分页 + 列显隐 + 排序            │
└──────────────────────────┴──────────────────────────────────────┘
  行点击 → 右侧 Drawer（≥1024）：
    [概要] memory_text / metadata / 双时态时间线（valid→invalid 区间）
    [来源] source_refs 反链 journal 原文对照（高亮命中段）★ 治理核心
    [操作] 查看任务链 / （跳转治理台执行操作）
```

- **关键交互**：`user_id` 为检索锚（与 API 语义一致）；摘要列 truncate + tooltip 全文；ID 点击复制
- **来源反链是本页灵魂**：每条 L3 记忆可回放其 journal 原文，人工核验「抽取是否有源、是否幻觉」—— 源文本交叉校验（memory_supported_by_source）的人工兜底入口
- **状态设计**：加载=骨架行；空态=引导输入 user_id（不是死白屏）；错误=内联 Alert + 重试
- **无障碍**：`<table>` 语义 + `scope=col`；Drawer（Radix Dialog）焦点圈闭、Esc 关闭、返回焦点至触发行；筛选表单纯键盘可达，结果计数 aria-live
- **响应式**：<1024 筛选栏收进 Sheet（vaul）；表格降级为卡片列表（保留：摘要/状态/槽位/时间），其余列收进详情；Drawer → 全屏 sheet

### P3 任务监控

**目的**：找到卡住/失败的任务，判断要不要人工干预。

- **布局**：状态 Tab（全部/RUNNING/FAILED/DEAD_LETTER）+ 年龄筛选 → 表格（task_id / op_type / scope / retry_count / 更新时间 / last_error 摘要）→ 展开行：result JSON 树视图 + `reclaimed` 孤儿回收标记（badge + tooltip 解释）
- **无障碍**：Tab 用 Radix Tabs（roving tabindex）；JSON 树 `role=tree`；错误单元格红色文字配错误图标
- **响应式**：Tab 保留、表格→卡片
- **设计细节**：`retry_count` 显色阶（0-2 默认 / 3-4 amber / 5=DEAD_LETTER violet）；「孤儿已回收」与「真失败」视觉区分

### P4 治理操作台（危险区）

**目的**：受控执行删除/更新/rebuild，任何危险操作可预览影响、可追踪。

- **流程设计**（三步向导）：
  1. 选操作 → 参数表单（zod 与后端 schema 同构校验，错误即时报）
  2. **影响预览**：删除前展示将影响的记忆数/会话数（v1 用 memories 检索计数；后端 dry-run 端点列 P2 增强）
  3. 确认执行：普通操作 Radix AlertDialog；**delete-all 额外要求手动输入 user_id 复述**（不可逆操作行业惯例）
- 提交后 toast 给出 task_id，一键跳任务监控
- **无障碍**：AlertDialog 焦点圈闭 + 危险按钮 `aria-describedby` 说明后果；表单错误 `aria-live=assertive` 播报；stepper `aria-current=step`
- **响应式**：移动端**仅可查看预览，执行按钮禁用**（Q4 决策）—— 置灰 + 文案说明而非隐藏

### P5 审计日志

- 只读表格：时间 / 操作者（token 标识）/ 动作 / 目标 / before→after diff（JSON diff 视图）/ 结果；按操作者/动作/时间筛选
- 依赖后端 audit 表（middleware 写入，delete-all 级操作必留痕）；v1 只读不导出
- 无障碍/响应式同 P2 模式（diff 移动端折叠为手风琴）

### P6 系统配置（只读）

- 分组 key-value 表（复用 Settings 分组）+ 环境徽标；敏感值默认 `••••` + 显隐切换（显隐记审计）
- 成本近零，价值在 on-call 排障「跑的到底是什么配置」一眼可查

## 4. 全局无障碍工程方案（AA 验收口径）

| 项 | 方案 |
|---|---|
| 键盘 | 全站无鼠标可达（Radix 默认）；全局焦点环 `:focus-visible`；Skip to content |
| 对比度 | 语义色 token 预校验 ≥4.5:1；CI 加 axe-core 冒烟（Playwright，critical 违例 fail） |
| 屏幕阅读器 | 路由切换 announce；异步状态变化 polite live region；表格/树/Tab 全 ARIA |
| 动效 | 尊重 `prefers-reduced-motion`；无纯动效传达信息 |
| 表单 | label 显式关联；错误不只用颜色；zod 消息即 aria 描述 |
| 验收 | 每页键盘走查清单 + axe 零 critical + 抽样 VoiceOver/NVDA 走查 |
