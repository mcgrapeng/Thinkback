# 全仓轮子审计 —— 业界方案复用核查（2026-09-24）

目标：审计全仓是否存在「重复造轮子」；业界存在优秀开源方案时必须复用。
方法：逐模块分类 —— **业界复用 OK / 领域策略（保留有据）/ 真·轮子（替换）**。

## 1. 审计结论

- **全仓 1 处真·轮子**：`memory/caches.py` 手写 TTL+容量缓存 → **已替换为 `cachetools.TTLCache`**（业界标准，~1 亿次/月下载；7.1.6 已在环境，转正为显式依赖）。
- 其余自研模块经逐项对标评估均为**领域策略或编排胶水**，业界无「更优秀的可直接复用件」——保留理由逐项列于 §3。
- 宏观复用现状良好：FastAPI/uvicorn/SQLAlchemy/Alembic/mem0/pymilvus/loguru/grpcio 均为业界主流件，无自造 Web 框架/ORM/向量库/迁移工具。

## 2. 已执行替换：BoundedTTLCache → cachetools.TTLCache

| 项 | 内容 |
|---|---|
| 替换物 | 63 行手写 dict 子类（TTL + 最旧写入淘汰） |
| 替换为 | `cachetools.TTLCache` 轻量适配层（保留服务调用面 `put`/`get_if_fresh` 与构造校验） |
| 语义差异 | 淘汰顺序 FIFO→LRU（缓存为 best-effort 读加速，正确性无影响）；过期判定走库内 monotonic 计时器 |
| 两处必要适配 | ① cachetools 7 `maxsize` 为只读 property → 「运行时改 `READ_CACHE_MAX_ENTRIES` 立即生效」语义改为**上限变更时整体重建**（`_active_memory_cache_synced` / `_summary_cache_synced`，生产上限恒定零重建，测试 test_memory_service:6689 守护）；② TTLCache 读到过期项会删除它（内部可变）→ 读路径补持 `_read_cache_lock`（原 dict.get 无副作用故不必持锁） |
| 验证 | 549 测试全绿 · ruff 干净 · mypy strict 零问题 |
| 依赖 | `cachetools>=5.3,<8` 转正显式依赖（原为传递依赖，直接引用有断链风险） |

## 3. 逐项对标评估（保留项及理由）

| 自研件 | 业界候选 | 决定 | 理由 |
|---|---|---|---|
| `memory/l3.py` L3WriteExecutor | 无直接对应库（concurrent.futures 之上的策略编排） | 保留 | own/inject 生命周期、容量背压、write/cleanup future 分账是业务编排非通用件 |
| `repositories/sqlalchemy.py` `_run` 同步-异步桥 | `asgiref.async_to_sync` | 保留 | asgiref 无单调用超时+取消内部任务语义、无专用事件循环线程的连接池一致性保证；自有生命周期（close/守卫/关机竞态）深度耦合 |
| `api/memory.py` 读写线程池+信号量 | starlette `run_in_threadpool` / anyio CapacityLimiter | 保留 | anyio 等价实现代码量相当；现有实现带独立读写预算与队列满 503 语义（测试断言文案），替换无净收益 |
| `_mutate_task_with_retry` CAS 重试 | `tenacity` | 保留 | 重试体是「重读快照→重放变更」的 CAS 策略（25 行），tenacity 只提供重试机制不提供重放语义，替换需重整锁边界 |
| `domain/slots` 8 正则抽取器 | LLM 抽取（mem0 内置） | 保留 | 决策 Q6：确定性骨架；槽位正则可解释/可测/零成本，mem0 LLM 抽取仍在 L3 后端内并行使用 |
| `domain/safety.py` 词表门禁 | moderation API / guardrails 框架 | 保留 | fail-closed 语义要求离线确定性；在线 moderation 引入延迟/成本/不可复现（自认局限已在 safety.py:6-8 注明） |
| `InMemoryMemoryRepository` / `FakeMemoryBackend` | 通用 fake/mock 库 | 保留 | 自有端口（Protocol）的测试替身，实现自有语义（CAS/指纹/墓碑），非通用轮子 |
| `script/real_mem0_*` 评测脚本 | deepeval / ragas / mem0 memory-benchmarks | 保留现脚本，**未来扩展须复用** | 现有脚本测自有指标（冲突污染/复活率/跨用户泄漏等通用库没有）；**路线图第一批的 LLM-as-judge 必须基于 deepeval/ragas 复用实现，不得手写 judge 框架** |
| L1 缓存 mixin / BoundedSemaphore 限流 / 指纹哈希 | — | 保留 | stdlib 之上的薄封装 |
