# 深度审美报告 — 记忆治理台 Web UI（2026-09）

> 审计人：Claude（资深 UI/UX 视角）｜方式：grilling 对齐后实测（69 条混合状态种子数据、明暗双模式、真实交互态）
> 基准：Linear/Vercel 系冷静灰阶 + 信息设计标准（已与 owner 对齐）
> 约束：appica token 体系与布局骨架保留，体系内打磨；shadcn/ui + Tailwind 内解决，不造轮子

---

## 一、总评

**这个台的底子是干净的，但它现在是一张「数据库视图」，不是「治理工作台」。**

设计系统（appica 五档灰阶、状态三档、Geist、焦点环）是合格甚至优秀的资产——暗色模式整体成立就是证明。问题不在色彩与组件，而在**信息设计**：机器键站在人的位置上（UUID 首列），治理的核心维度不可见（表格无用户列），时间的粒度全部给满（双绝对时间戳列），空缺没有被设计（裸「—」），交互态缺席（行无 hover）。六页骨架一致性尚可，但空态、表格规范各页各说各话。

一句话：**token 是 80 分的，信息编排是 50 分的，观感被后者拖到 65 分。** 改版不需要换血，需要把每一列、每一态重新按「人先读什么」排序。

## 二、Severity 定义

| 级别 | 定义 |
|---|---|
| **P0** | 信息架构伤害：该看的信息看不到 / 不该看的信息占据主位，影响任务完成 |
| **P1** | 视觉层次伤害：信息都在但编排失当，增加扫读成本 |
| **P2** | 打磨项：细节质感、一致性、态设计 |

## 三、主样本深挖：/memories（记忆浏览器）

### P0

**F1 · 表格没有「用户 / 范围」列。**
过滤器可以按用户筛，但行上看不到这条记忆属于谁。六个人的数据混排，治理台的核心实体（谁的记忆）在主视图不可见。抽屉里有「用户 u-carol / 范围 thinkback」，证明数据一直都在，只是表格没给位置。
**改法**：加「用户」列，中性 chip 承载 `user_id`，点击即应用该筛选（chip 即过滤器，所见即所筛）。范围并入 chip 次级文本或 tooltip。

**F2 · 完整 UUID 占据首列。**
`memory-074ee3c1-1780-4f02-941e-0c4ff0830062` 整根竖在最左，约占表格视觉质量的 40%，把真正要读的记忆文本挤到右侧与噪音竞争。这是 database dump 的排版，不是浏览器的排版。
**改法**（已对齐）：文本领头；ID 降级为 mono 短 hash（`074ee3c1`，取 UUID 前 8 位），次级色，hover 出全量 + 复制。参照 Linear issue ID / GitHub commit hash。

### P1

**F3 · 记忆文本无截断，长文本摧毁行节奏。**
超长记忆整段展开（实测 4 行），行高失去统一节奏，扫读时视线被迫上下跳跃。
**改法**（已对齐）：`line-clamp-2` + 行高下限统一，全文进抽屉（已有）。

**F4 · 双绝对时间戳列 = 时间噪音。**
`2026/09/24 14:18:19` × 每行两根。人对「什么时候」的读取粒度是「今天 / 上周 / 三个月前」，精确到秒的时间戳是审计归档语义，不是扫读语义。
**改法**（已对齐）：主显相对时间（`3 天前`），hover/tooltip 给完整绝对时间戳；**失效时刻列仅在非空时渲染**（值本身或整列按数据条件出现），非 ACTIVE 行的失效时刻用次级色。空的「—」不配占一整列的视觉位。

**F5 · 行零 hover 态。**
代码验证：memories.tsx 中行上没有任何 `hover:bg`。副标题写着「点击行查看详情与来源反链」，行却不声明自己可点——无 hover 背景、无 cursor-pointer、无 chevron。可发现性全靠文案。
**改法**：`hover:bg-background-subtle` + `cursor-pointer` + 行尾 chevron-right（次级色）。三件套一起上，缺一不可。

**F6 · 筛选无结果的空态 = 表头 + 「共 0 条」，什么都没有。**
实测：筛不存在用户后表格只剩列头和页脚计数。tasks 页有完整的虚线框空态（图标+标题+引导+CTA），memories 没有。同一个产品两种「空」。
**改法**：统一空态组件（下文规格 S6），memories 空态文案引导「清除筛选」而非「新建」。

**F7 · 错误态文案误导。**
任何请求失败统一渲染「请确认后端服务可达、管理 token 正确」。实测后端挂掉时确实如此——但这句把所有故障都归因给用户环境。筛选参数错误、5xx、超时应区分或至少给出中性的「加载失败 + 重试」。
**改法**：`加载失败` + 重试按钮 + 可展开的错误详情；诊断文案留给详情层。

### P2

**F8 · 「槽位」列 ~80% 是「—」。**
conflict_slot 由文本派生，绝大多数行无槽位。一列五分之四是空的，等于在表格里养了一根常驻空线。
**改法**：槽位并入记忆文本下方作为次级元信息行（`pet_name:cat` mono chip，仅非空时），或与「类型/敏感等级」合并为元信息列。表格列数从 7 → 5-6。

**F9 · 召回次数是裸数字。**
0、5、13、89 右对齐排一列，无视觉编码。召回热度是治理决策（该不该衰减）的输入，值得 1px 的编码。
**改法**：mono 数字 + 轻量热度（0 显示为次级「—」或 0；高值 foreground-intense）。不做进度条——表格里禁止图形化过头。

**F10 · 筛选区是无成组关系的控件堆。**
三个控件靠 placeholder 自证身份，「检索」「重置」与过滤器之间无视觉成组。副文案「用户 ID / 范围 / 状态」浮在控件上方像临时脚手架。
**改法**：筛选区整体收进一个 `background-subtle` 圆角容器，与表格卡片形成「工具条 → 结果」的父子关系；label 改为控件左侧 64px 固定标签列（对齐 dev tools 惯例），去掉 placeholder 里的重复信息。

**F11 · 抽屉底部双危险动作无隔离。**
「重建索引」（安全）与「删除记忆」（destructive）并肩站。误点距离 8px。
**改法**：删除右移+左加分隔线，或收进 `⋯` 菜单；删除本身应有 confirm（当前未见确认层）。

**F12 · 页脚分页为纯文本。**
`共 69 条 · 1/2 页` + 上一页/下一页，可用但每页 50 固定。数据量过百后需要 page-size（20/50/100）与跳页。优先级低，随 P2 一批做。

## 四、其余五页一致性走查

### /overview（总览）
- **F13 (P1) · 记忆分布条形图是「假图表」。** 六根等长灰条 + 重复数字（12/13/12/11/12/11），无坐标、无最大值高亮、无悬停。图表存在的意义是让比较发生——现在它只是把数字竖着又排了一遍。
  **改法**：最大值条用 foreground-intense，其余 foreground-soft；条内右对齐 mono 数值；加 hover tooltip（用户、条数、活跃/删除占比）。不引图表库，CSS 条即可。
- **F14 (P2) ·「写入测试记忆」是调试动作，不该出现在页头。** 页头是产品级动作位。移进下拉或 govern 页。
- **F15 (P2) · 0 值指标与真实指标无差别。** 「任务总数 0」「审计事件 0」的大数字与「记忆总量 69」视觉权重完全相同。0 是「无事发生」也是「无数据」，应有次级处理（数字次级色 + 「暂无」语义）。

### /tasks（任务中心）
- **F16 (P1) · 失败任务的 last_error 不可见。** 死信/失败行的最重要诊断信息（`retry exhausted: milvus timeout`）没有任何入口。运维场景这是第一诉求。
  **改法**：失败/死信行可展开（row expansion）显示 last_error mono 块 + 重试次数；或行尾「详情」开抽屉，与 memories 抽屉范式统一。
- **F17 (P2) · 双时间戳噪音与 memories 同款**（创建时间+更新时间）。同 F4 改法；「耗时」列是好设计，保留。
- 空态（虚线框+图标+CTA）是六页里最好的一个，作为基准范式。

### /govern（治理策略）
- **F18 (P1) · 长表单无 sticky 保存栏。** 保存策略只在页头，页面两屏多高，滚到底部改完滑轮要回顶部才能保存。代码验证无 sticky。
  **改法**：底部 sticky 操作条（脏时出现：`有未保存的修改` + 恢复默认/保存），或页头按钮随脏状态置灰提示。前者更治理台。
- **F19 (P2) · 衰减曲线是全站唯一「被设计」的时刻，是好榜样。** 章节式定义列表布局（左标签右控件）成熟。问题只是单调：六个 section 同构卡片阵。给「记忆保留策略」这类核心 section 加权重（标题档位提升），次要 section 收紧。
- 恢复默认无 confirm（与 F11 同类，destructive/不可逆动作缺确认）。

### /audit（轮换审计）
- **F20 (P1) · detail JSON 不可见。** 审计事件的 detail（reason、before/after status）是审计的核心内容，表格里没有，也未见展开入口。与 F16 同病：**信息在库里，不在屏上**。
  **改法**：行展开或抽屉显示 detail 结构化字段（不要裸 JSON dump：reason 中文、状态迁移用徽章对）。
- 骨架屏已有（h-10 行），好评。

### /config（系统配置）
- **F21 (P2) · 4000px 单列长滚，无锚点导航。** 六个 section 顺排，找「功能开关」要靠滚动狩猎。
  **改法**：左侧锚点小导航（section 内 scrollspy 高亮），或 section 收纳为手风琴（默认展开前两个）。配置页是低频页，手风琴更省。
- 敏感配置掩码 + mono 值排版是全站细节最好的一段，保持。

## 五、暗色模式专项

结论：**token 体系扛住了，无 P0/P1。** 五档灰阶在 #030712 底上层次成立，状态徽章 soft 底在暗卡面上可读，衰减曲线渐变在暗色下反而更好看。

- **F22 (P2) · 表格行的「—」空缺在暗色下对比度进一步塌陷**（foreground-soft on background-card）。空缺表达要在两种模式下都成立——这也是把空缺从「裸字符」升级为「设计的空」的理由之一。
- **F23 (P2) · hover:bg-background-subtle 在暗色下偏弱**（#0a0d18 on #030712 差一档不够）。改版时暗色行 hover 用 `background-muted`（#101828）。

## 八、负面清单（负面约束，改版与后续新增页一律遵守）

1. 禁渐变装饰（数据可视化中的面积渐变除外，如衰减曲线）
2. 禁彩色装饰图标——图标只用 foreground 系；颜色只承担状态语义
3. emoji 仅允许空态插画位
4. 圆角 ≤ 10px（现有 token 体系即是）
5. 卡片阴影只出现在 popover/dialog/sheet；表格与卡片分层靠边框五档，不靠阴影
6. 表格内禁止图形化编码过头（进度条、仪表盘）；数字+色阶即上限
7. 无假数据装饰（无头像数据就不造头像圆点）
8. 机器键（UUID/hash）永远不占人类阅读的第一视觉位

## 九、改版规格（对齐决策的落地参数）

### S1 · memories 表格列序（重构后）

```
[记忆文本]        [状态] [用户] [生效] [召回] [hash]
 2行clamp·主宽      徽章  chip   相对   数字   mono·次级
 记忆文本下方次级元信息行: 槽位chip · 类型 · 敏感等级（仅非空项）
```

- 列宽比例 ≈ 42 / 10 / 14 / 12 / 8 / 14（%）
- 失效时刻：不设列；非 ACTIVE 行在「生效」格内第二行以 `→ 失效 3 天前` 次级色呈现
- hash 列：`074ee3c1`（8 位），click 复制 + toast，hover 下划线（沿用现有交互）

### S2 · 时间格式

- 表格内：相对时间（`刚刚 / 5 分钟前 / 3 天前 / 2 个月前`），`title` 属性带完整 `2026-09-24 14:18:19 +08:00`
- 抽屉/详情：完整绝对时间（审计语义在场的地方给满粒度）
- 实现：day.js `relativeTime`（如未装）或 20 行工具函数——不引大库

### S3 · 用户 chip

- `bg-background-muted` 圆角 6px，`u-alice` mono 13px + scope 次级后缀
- 点击 = 应用该用户筛选（chip 即过滤器）
- 无假头像（负面清单 #7）

### S4 · 行交互三件套

`hover:bg-background-subtle（暗色 background-muted）` + `cursor-pointer` + 行尾 chevron-right（foreground-soft）

### S5 · tasks/audit 行展开

- 失败/死信/审计行：行尾 chevron 切换展开区，展开区 `background-subtle` 内嵌 last_error（mono, error 色）或 detail 结构化字段
- 150ms ease-out 高度动画

### S6 · 统一空态组件 `<EmptyState variant="initial|filtered" />`

- 图标 40px foreground-soft + 标题 15px emphasis + 一句话 muted + 单个动作按钮
- initial：「还没有记忆」+ 引导写入；filtered：「没有匹配的记忆」+ 清除筛选
- 采纳 tasks 现有虚线框容器为壳

### S7 · govern sticky 保存条

- 表单脏时底部浮出：`background-inverse`（亮色 #101828 深条）白字 + 恢复默认（ghost）+ 保存（primary 反色）；不脏不占位

### S8 · 错误态组件

`加载失败` 标题 + 重试 primary + 「查看详情」折叠（mono 错误体）。替换现有误导文案。
